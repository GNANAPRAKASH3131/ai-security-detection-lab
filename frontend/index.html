🏆 Core Research Findings: What Does AI See, What Does It Miss, and Why?
This synthesis summarizes findings from 7 controlled research experiments simulating an adversary who has already achieved an internal foothold on a workstation (WIN-LAB01: 10.10.10.20).
1. DETECTED 4 Scenarios
Why was it detected?
  • High Destination Novelty: Standard workstation user suddenly authenticating to Domain Controller and Linux DB Server.
  • Velocity Spikes: 5+ failed logons in <60 seconds triggered statistical z-score burst rules.
  • Explicit Privilege Jumps: Adding user01 to Domain Admins (EID 4728) produced anomaly score = 0.96.
  • High-Risk Binaries: Execution of nltest.exe and psexec matched deterministic SIEM rules.
2. MISSED Telemetry Gap
Why was it missed?
  • Telemetry Interruption: An AI detection system cannot detect what it cannot observe (0 events received = 0 score).
  • Collector Suppression: When endpoint logging was paused, Invoke-Mimikatz executed with 0 alerts produced.
  • Living off the Land: Low-and-slow single commands spaced over hours fall beneath rolling sliding-window thresholds.
3. PARTIAL Mixed Segments
Why was it partial?
  • Asymmetric Forwarding: If endpoint process logs are enabled but network sensors are offline, port sweeps appear only as isolated processes.
  • Degraded Collector Rate: Intermittent dropping lowers anomaly confidence below the 0.61 alerting threshold.
Internal Penetration Tester's Technical Analysis Adversary Perspective
1. AI Is Dependent on Telemetry Ingestion: Statistical anomaly engines operate exclusively on ingested logs. Tampering with or exhausting the endpoint logging agent completely neutralizes behavioral defense.
2. Living off the Land & Business Hours: Adversaries executing built-in administrative tools (PowerShell, MMC, WMI) during regular business hours generate low novelty scores ($<0.30$) if volume remains moderate.
3. Context Disconnect: AI models measure mathematical baseline deviation, but cannot understand business intent (e.g. distinguishing an authorized script from an attacker running the same command).
Actionable Security Recommendations for Blue Teams Defensive Engineering
1. Agent Heartbeat Monitoring: Alert immediately if any workstation or server agent stops transmitting heartbeats for $>60$ seconds.
2. Independent Out-of-Band Network Telemetry: Deploy network flow sensors (Zeek/Suricata) that endpoints cannot disable or tamper with.
3. Dual-Layer Defense Strategy: Combine deterministic signatures (Sigma/YARA) with behavioral models to prevent single-point detection failures.
4. Just-In-Time (JIT) Privileged Access: Eliminate persistent domain admin privileges on workstations to prevent credential reuse.
